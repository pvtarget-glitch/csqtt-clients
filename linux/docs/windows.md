# csqtt на Windows

Тестовая сборка для Windows 10 и 11 (x64), проверялась в GitHub Actions на Windows Server 2025. Внутри то же окно (значок в области уведомлений), служба `csqttd` и команда `csqtt`, что и в версии для Linux. Установщик: `csqtt-windows-…-x64-setup.exe`.

## Установка

1. Скачай `csqtt-windows-…-x64-setup.exe` из [Releases](https://github.com/pvtarget-glitch/csqtt-linux/releases).
2. Установщик не подписан, поэтому SmartScreen покажет «Windows защитила ваш компьютер». Нажми «Подробнее» → «Выполнить в любом случае».
3. Установщик спросит права администратора. Он кладёт программу в `C:\Program Files\csqtt`, ставит и запускает службу `csqttd` (автозапуск, от имени LocalSystem) и драйвер [Wintun](https://www.wintun.net) от авторов WireGuard.
4. Запусти csqtt из меню «Пуск».

Управлять туннелем может любой пользователь, вошедший в систему. Остальное — как на Linux: добавь сервер по ссылке `csqtt://`, укажи хеши VK-звонков и подключись. Окно проверки VK открывается внутри приложения.

Команда `csqtt` лежит рядом с программой: `"C:\Program Files\csqtt\csqtt.exe" status`. Профили хранятся в `%APPDATA%\csqtt`, настройки службы — в `C:\ProgramData\csqtt\csqttd.toml` (если файла нет, действуют значения по умолчанию).

Установка сервера на VPS из окна использует встроенный в Windows клиент OpenSSH (`ssh.exe`, есть в Windows 10 1809 и новее).

## Как это устроено

```text
программы → маршруты 0/1 и 128/1 через адаптер csqtt → служба → UDP 127.0.0.1 → ядро csqtt
ядро → серверы VK: сокеты привязаны к физическому интерфейсу (IP_UNICAST_IF)
```

- Служба создаёт адаптер Wintun `csqtt` и направляет в него весь IPv4-трафик двумя маршрутами `/1`. Маршрут по умолчанию не трогается, локальная сеть доступна.
- Пакеты из адаптера служба пересылает ядру по UDP на 127.0.0.1. Ядро принимает их только с адреса службы (`--listen-peer`).
- Своё соединение с VK ядро держит через физический интерфейс (`--bind-interface` с номером интерфейса), поэтому оно не попадает в собственный туннель.
- DNS туннеля ставится на адаптер `csqtt`, у него самая низкая метрика, поэтому Windows спрашивает его первым.
- IPv6 направляется в адаптер маршрутами `::/1` и `8000::/1` и не проходит: туннель передаёт только IPv4.
- Если ядро упало, адаптер и маршруты остаются, и трафик не уходит мимо туннеля, пока ты не отключишься. Если остановить саму службу, адаптер удаляется вместе с маршрутами и DNS.

## Удаление

«Параметры → Приложения → csqtt → Удалить». Служба останавливается и удаляется вместе с программой. Профили в `%APPDATA%\csqtt` остаются.

## Чего пока нет

- «Программ мимо туннеля» и режима «только выбранные программы» — они есть только в версии для Linux.
- Исключений по IP из настроек маршрутизации (исключения по доменам работают — их делает ядро).
- Блокировки трафика через фильтры Windows (WFP) на время переподключения и после остановки службы.
- Подписи установщика.

## Что проверено

В GitHub Actions на Windows с имитатором ядра — 10 проверок. Служба создаёт адаптер Wintun с адресом туннеля, ставит маршруты и DNS, ядро запускается в UDP-режиме с привязкой к физическому интерфейсу, `ping` через туннель доходит до ядра, и ответ возвращается. При отключении маршруты снимаются. Установщик ставится без вопросов (`/S`), служба запускается, `csqtt status` отвечает, окно запускается, удаление убирает службу и файлы.

Не проверено: работа с настоящими серверами VK и csqtt, окно на настоящем экране, установка сервера на VPS из Windows.
