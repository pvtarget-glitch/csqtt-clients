# csqtt на macOS

Тестовая сборка для macOS (проверялась в GitHub Actions на macOS 15): окно в строке меню, служба и команда `csqtt` — те же, что в версии для Linux. Пакеты: `csqtt-macos-…-arm64.pkg` для Apple Silicon (M1 и новее) и `csqtt-macos-…-x86_64.pkg` для Mac на Intel.

## Установка

1. Скачай `.pkg` для своего Mac из [Releases](https://github.com/pvtarget-glitch/csqtt-linux/releases).
2. Пакет не подписан сертификатом Apple, поэтому двойной щелчок покажет предупреждение. Открой «Системные настройки → Конфиденциальность и безопасность» и нажми «Всё равно открыть» рядом с сообщением о csqtt. Либо в Finder щёлкни пакет правой кнопкой → «Открыть».
3. Установщик кладёт `csqtt.app` в «Программы», службу `csqttd` (запускается через launchd от root) и команду `csqtt` в `/usr/local/bin`.
4. Запусти csqtt из «Программ». При первом запуске macOS тоже может спросить разрешение — так же через «Конфиденциальность и безопасность».

Управлять туннелем могут администраторы этого Mac. Всё остальное — как на Linux: добавь сервер по ссылке `csqtt://`, укажи хеши VK-звонков и подключись. Окно проверки VK открывается внутри приложения.

## Как это устроено

```text
программы → маршруты 0/1 и 128/1 через utunN → служба → UDP 127.0.0.1 → ядро csqtt
ядро → серверы VK: сокеты привязаны к физическому интерфейсу (IP_BOUND_IF)
```

- Служба создаёт интерфейс `utun` и направляет в него весь IPv4-трафик двумя маршрутами `/1`. Маршрут по умолчанию остаётся нетронутым, локальная сеть доступна.
- Пакеты из `utun` служба пересылает ядру по UDP на 127.0.0.1. Ядро принимает их только с адреса службы (`--listen-peer`).
- Своё соединение с VK ядро держит через физический интерфейс (`--bind-interface`), поэтому оно не попадает в собственный туннель.
- DNS туннеля ставится основному сетевому сервису через `scutil`, исходный сохраняется и возвращается при отключении.
- IPv6 на время работы направляется в `utun` и не проходит: туннель передаёт только IPv4.
- Если ядро упало, `utun` и маршруты остаются, и трафик не уходит мимо туннеля, пока ты не отключишься.
- Исключения по IP из настроек маршрутизации получают свои маршруты через шлюз физического интерфейса и идут мимо туннеля.

## Блокировка мимо туннеля (pf)

Пока туннель включён, служба держит правила встроенного в macOS брандмауэра pf в якоре `com.apple/csqtt`. `/etc/pf.conf` при этом не меняется. Мимо туннеля разрешены только:
- само ядро (по его пользователю `nobody`);
- локальная сеть, link-local, multicast и DHCP;
- исключения по IP.

Остальной трафик, IPv4 и IPv6, мимо туннеля не проходит. Это касается и программ, которые сами привязываются к Wi-Fi или Ethernet. DNS мимо туннеля (порт 53) запрещён и в локальную сеть.

При отключении правила снимаются. Если служба упала, launchd перезапускает её, и она первым делом снимает оставшиеся правила. Выключить блокировку: `kill_switch = false` в `/usr/local/etc/csqtt/csqttd.toml`, затем `sudo launchctl kickstart -k system/io.github.csqtt.daemon`.

## Удаление

```sh
sudo /usr/local/share/csqtt/uninstall.sh
```

Профили в `~/.config/csqtt` остаются.

## Чего пока нет

- «Программ мимо туннеля» и режима «только выбранные программы» — они есть только в версии для Linux. На macOS это делается только через системное расширение Network Extension, а для него нужны платный аккаунт разработчика Apple и разрешение Apple.
- Подписи Apple и нотаризации: нужен платный аккаунт разработчика.

## Что проверено

В GitHub Actions на macOS (Apple Silicon) с имитатором ядра — 22 проверки: служба создаёт `utun` с адресом туннеля, ставит маршруты (и маршрут исключения по IP через физический интерфейс), включает pf (соединение и DNS-запрос через физический интерфейс блокируются, после отключения сеть снова открыта), ядро запускается в UDP-режиме с привязкой к физическому интерфейсу, `ping` через туннель доходит до ядра, и ответ возвращается. DNS туннеля применяется. При отключении маршруты, `utun` и DNS возвращаются как были. Установщик `.pkg` ставится, служба запускается через launchd, `csqtt status` отвечает.

Не проверено: работа с настоящими серверами VK и csqtt на Mac, окно в строке меню на настоящем экране, сборка для Intel на настоящем Mac.
